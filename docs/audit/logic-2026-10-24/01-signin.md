## Checked and OK

- Host normalisation against .NET `Uri` (`try_normalize_host`): https added only without a scheme, scheme and host lower-cased, default ports dropped, user info / path / query / fragment dropped, IPv6 in brackets, IDN to punycode (requests identical), only http(s). `is_plausible_token`, `rewrite_to_host`, `same_origin`.
- Status mapping per endpoint against upstream: `/api/me` 401/403 none, other failures an error (`Unreachable` at sign-in); `send_json` 401/403 `Unauthorized`, other refusals with the server's sentence and reason; reads 401/403 / status; disk report 401 / 403 / 404 (diagnosed through `/api/me`) / other; client settings 401/403/413 stop until sign-in, 409 carries the winner, other statuses keep what we have; theme failures read as "the server would not say". Timeouts: 20 s requests, 15 s theme, 30 s disk report, 10 min approval.
- Loopback listener and pickup: 127.0.0.1 and an OS port, constant-time state compare, wrong state answered and ignored, CORS and private-network grant to the server's origin only, header and body limits, 10 s per connection, 16 at once; pickup every 2 s without `x-api-key` or redirects, 400/405/413/415 stop it, anything else waits, a 200 without token or error is not an answer; first answer wins; denial and `access_denied` mapping; cancel and the 10-minute timeout; confirmation code (server's test vector `554-LIO`) shown only while waiting, translated in both languages. My area's tests against 127.0.0.1:8420 pass (`me_identifies_tokens_and_refuses_strangers`, `the_skin_round_trips`, `client_settings_are_versioned`, `the_disk_report_needs_an_administrator_and_a_full_token`, `the_loopback_listener_ignores_strangers_and_takes_our_answer`, `browser_sign_in_end_to_end`), and the stand-in pickup tests.
- Sign-in window against `SignInViewModel`: stored card then check, statuses and tones, heading when an error shows, manual token, sign-out blocked while busy, Close/Escape cancel, generations against late answers, avatar answers keyed by generation.
- Account store: token bound to the origin it was issued for (W1), `adopt` never touches host or token and writes only on change, sign-out keeps the host (and the avatar, as upstream). Administrator flag: exact `admin`, tied to host and tag, never persisted.
- Settings sync: `decide` checked branch for branch against `ModlightSettingsPlan` (fresh-install guard, marker of another account discarded, push against the version just read); schema verdicts; allow-list and task-settings normalisation; merge rules (arrays replaced, explicit null merged); an open settings window blocks an adopt and its marker; conflicts are not retried in the same round; oversize said once; timings 45 s / 15 min / 20 s debounce; a sign-in's round waits for a running one instead of being dropped (upstream drops it). An adopt still nudges one extra round 20 s later (upstream suppresses nudges during its own apply); with L1 fixed that round only reads and finds nothing to do, so it was left as is.
- Skin sync direction (unconfirmed local pick pushed, otherwise the server's adopted; unknown skins recorded but not painted) and the push when Settings closes. No loops between skin sync, settings sync and saves.
- Updates: build-time https host or nothing, manifest parsing and refusals one reason at a time, numeric version compare that never downgrades, file names that cannot leave the folder and only this system's extensions, size and SHA-256 before the file is revealed, redirects only to https.
- Server tab words against `AdminDiskViewModel` (pressure, legend, shares against the server's own totals, Polish plural forms, cold and trash texts). Absurd numbers from a server wrap in release builds as upstream's unchecked C# does; only debug builds would panic.
- Keychain store: the secret goes through `security -i` on standard input, hex-encoded, read back after writing; item names validated; delete treats "not found" (44) as done.
- `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -D warnings`, and the tests of the touched crates: modlight-api (lib 39, `signin_pickup_fake` 4, the six reference tests above), modlight-core (lib 377, `settings_sync` 4), modlight-app (lib 51, `snapshots`).
