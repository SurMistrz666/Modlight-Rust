## 4. Outside my area

- **srv-media, `server/src/media/actions.rs` `delete_media_bulk` and `delete_media_hard` (medium,
  quota bypass, same in upstream):** both refund `used_quota` for the rows they were HANDED, not
  for the rows their `DELETE` removed. Two concurrent permanent deletes of the same file (two
  parallel `DELETE /api/uploads {"mode":"permanent"}` with a `write` token, a double-clicked
  "Delete forever", two "Empty trash" calls, `POST` twice on a deletion link, or a call racing the
  trash sweep) each delete the object, each run the `DELETE` (the second removes nothing) and each
  refund the size. Repeating "upload, trash, delete twice in parallel" walks `used_quota` down to 0
  while the files stay. Callers in my area: `uploads.rs` `empty_trash_for`,
  `actions/uploads.rs` `delete_upload_forever`, `routes/api/uploads.rs` DELETE,
  `routes/media_delete.rs`, `actions/admin_library.rs`. Recommended fix (the one SRVF-05 applies to
  the sweep): `DELETE ... WHERE id = ANY($1) RETURNING owner_id, size` (and `RETURNING` in
  `delete_media_hard`), refund and count only what came back.
